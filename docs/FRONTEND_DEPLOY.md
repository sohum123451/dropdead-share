# Frontend Production Deployment Guide (AWS S3 & CloudFront)

This guide documents deploying the React 19 + Vite frontend application as a statically hosted Single Page Application (SPA) using AWS S3 and Amazon CloudFront CDN, with essential custom error response mappings to enable deep-linking (e.g., `/d/:token`).

---

## 1. Architecture Overview

- **Storage**: AWS S3 private bucket containing built static assets (`frontend/dist/`).
- **CDN**: Amazon CloudFront providing global edge caching, HTTP/3, and automatic TLS/SSL.
- **Access Control**: CloudFront Origin Access Control (OAC) to ensure S3 assets cannot be accessed directly bypassing CloudFront.
- **Client-Side Routing (SPA)**: Custom error response routing mapping 403 Forbidden and 404 Not Found to `/index.html` with HTTP 200 OK status.

---

## 2. AWS S3 Static Bucket Setup

1. Create a dedicated S3 bucket (e.g., `dropdead-frontend-prod`).
2. Keep **Block all public access** enabled on the bucket.
3. Bucket policy will allow read access exclusively from the CloudFront Origin Access Control (OAC).

---

## 3. CloudFront Distribution & SPA Deep-Link Routing

### 3.1 CloudFront Distribution Configuration
1. **Origin Domain**: Select the S3 bucket (`dropdead-frontend-prod.s3.amazonaws.com`).
2. **Origin Access**: Choose **Origin Access Control (OAC)** and create a new control setting.
3. **Viewer Protocol Policy**: Select `Redirect HTTP to HTTPS`.
4. **Allowed HTTP Methods**: `GET, HEAD, OPTIONS`.
5. **Default Root Object**: `index.html`.

### 3.2 S3 Bucket Policy (Auto-generated by CloudFront OAC)
Attach this policy to the S3 bucket so CloudFront can read the assets:

```json
{
  "Version": "2012-10-17",
  "Statement": [
    {
      "Sid": "AllowCloudFrontServicePrincipalReadOnly",
      "Effect": "Allow",
      "Principal": {
        "Service": "cloudfront.amazonaws.com"
      },
      "Action": "s3:GetObject",
      "Resource": "arn:aws:s3:::dropdead-frontend-prod/*",
      "Condition": {
        "StringEquals": {
          "AWS:SourceArn": "arn:aws:cloudfront::<ACCOUNT_ID>:distribution/<DISTRIBUTION_ID>"
        }
      }
    }
  ]
}
```

### 3.3 SPA Deep-Link Fallback Rule (Critical for `/d/:token`)
Because the app uses client-side routing with React Router, a direct visit or browser refresh on `/d/:token` will query S3 for the non-existent key `d/:token`, causing S3 to return `403 Forbidden` or `404 Not Found`.

Under the CloudFront distribution's **Error pages** tab, add two custom error responses:

#### Error Response 1: 403 Forbidden
- **HTTP Error Code**: `403: Forbidden`
- **Customize Error Response**: Yes
- **Response Page Path**: `/index.html`
- **HTTP Response Code**: `200: OK`
- **Error Caching Minimum TTL**: `0`

#### Error Response 2: 404 Not Found
- **HTTP Error Code**: `404: Not Found`
- **Customize Error Response**: Yes
- **Response Page Path**: `/index.html`
- **HTTP Response Code**: `200: OK`
- **Error Caching Minimum TTL**: `0`

## 4. Build and Deployment Pipeline

### 4.1 Production Environment Variables
Set `VITE_API_URL` to point to the production backend API domain in `.env.production`:

```env
VITE_API_URL=https://api.example.com
```

### 4.2 Build Command
```bash
cd frontend
npm run build
```

### 4.3 Sync Assets to S3 and Invalidate CloudFront
```bash
# Upload assets with long-term cache for hashed files and no-cache for index.html
aws s3 sync dist/ s3://dropdead-frontend-prod/ --delete --exclude "index.html" --cache-control "public, max-age=31536000, immutable"
aws s3 cp dist/index.html s3://dropdead-frontend-prod/index.html --cache-control "no-cache, no-store, must-revalidate"

# Invalidate CloudFront cache
aws cloudfront create-invalidation --distribution-id <DISTRIBUTION_ID> --paths "/*"
```
